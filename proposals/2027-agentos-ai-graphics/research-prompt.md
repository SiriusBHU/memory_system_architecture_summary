## 1. 立项范围（已定，不要改动）

### 1.1 Agent OS：围绕「Agent + 应用叠加」场景，提升系统内存供给和模型运行效率

**总体构想（放在最前面讲）**：模型内存成为系统的一等公民——统一记账、可回收、可共享。

**三个关键技术**

- **KT1 智慧化内存管理**（对象：应用和 Agent 中**非模型**部分的内存）
  - **KT1-a .so 文件页锁优化**：降低 Agent 与应用叠加时的锁竞争，提升应用冷启动性能。对象主要是 .so（共享库）的文件页；NPU 相关的文件映射归 KT3。
  - **KT1-b 基于 ARM SPE（含扩展）的匿名页冷热识别与预取**：提升叠加场景的运行流畅度。换出后端是 zram。
  - **KT1-c 基于同一套冷热识别的匿名页换出（zram）**：降低系统内存压力。预取和换出分开，作为两个子技术来讲。
- **KT2 Agent 内存组件**：MoE 专家缓存（LRU 等替换策略，提升专家命中率）；KV Cache 的回收与压缩。
- **KT3 模型翻译组件**：模型加载、卸载提速，重点是 IO；用类似零拷贝的映射方案降低内存浪费、提升 IO 利用率（包括 NPU 侧的文件映射）。

**支撑能力：性能跟踪与优化（基于仿真平台）**

- **S1** Agent 云转端的性能、功耗代价与成本收益评估。其中的**风险评估**包括：真机可观测性与体验指标、标准负载集、仿真校准。
- **S2** Agent 并行化方案的导出与仿真验证，只看**单个 Agent 内部**的并行：并行工具调用、并行子任务、投机执行、CPU/GPU/NPU 流水。

### 1.2 AI + 图形：提升用户体验（不与系统功能挂钩）

- **G1** 3DGS 持续优化
- **G2** AI 萌宠
- **G3** 神经渲染
- **G4** 生成式 UI：模型生成界面的渲染与交互体验

### 1.3 明确不做

以下内容在洞察里可以作为业界事实提及，但不作为我们的方案：跨 IP 的带宽、算力、温度 QoS；按 Agent 语义调整前后台资源策略；多 Agent 并发；端侧后台 Agent（2028 年前）；GUI Agent。

## 3. 各技术点必须回答的调研问题

### KT1（系统内存）

- **.so 冷启动**
  - Linux 内核中的相关锁：mmap_lock、per-VMA lock（从哪个版本起覆盖文件页缺页）、folio lock 与 major fault 的 I/O 等待、i_mmap_rwsem（共享库被多进程映射时，以及反向映射回收时）、lru_lock、readahead。
  - arm64 可执行段的大 folio / contpte 优化，确认合入的内核版本。
  - 内存压力下 .so 页被逐出、对冷启动造成影响的公开数据。
  - 鸿蒙内核的对应机制（如有公开资料）。
- **ARM SPE**
  - 机制：Armv8.2 起的可选特性，采样记录的地址、延迟、data source 等；Linux 内核的支持情况。
  - 手机 CPU 核（Cortex-X/A 系列、华为泰山核）是否实现 SPE，量产设备是否放开。
  - 基于 SPE 做热页识别或内存分层的内核补丁、论文。
  - 先例：Intel PEBS（HeMem、Memtis）、AMD IBS（内核热页追踪 RFC）、DAMON 引入硬件采样的讨论。
  - 采样开销数据。
  - 采样「容易证明页是热的、很难证明页是冷的」这一问题，以及业界的补救办法。
- **zram 换出与预取**
  - Android zram 的现状、page-cluster 设置、zram writeback、MGLRU、memcg 按应用回收。
  - 厂商做法：三星 RAM Plus、国内厂商的内存扩展、应用切回前台时的批量换入。
  - iOS 与 HarmonyOS 的对应机制。
- **背景数据**：2025–2026 年手机 DRAM 价格，以及旗舰、中端机型内存容量的变化。

### KT2（MoE 与 KV Cache）

- **MoE**
  - 2025–2026 年发布的端侧或小型 MoE 模型。
  - 2027 年端侧 MoE 会不会成为主流？「专家缓存」是否应该泛化为「稀疏权重分层」（专家 / PLE / 激活稀疏神经元）？给出判断和依据。
  - 专家卸载、缓存、预取方法（EdgeMoE、PowerInfer-2、MoE-Infinity、HOBBIT、AdapMoE、ProMoE、Pre-gated MoE、LLM in a flash 等，核实年份和发表会议）报告的命中率和 tokens/s。
- **KV Cache**
  - 量化（KIVI 等）、淘汰（H2O、SnapKV、StreamingLLM）、Apple 端侧模型的 KV 共享、前缀 KV 的复用与持久化、KV 卸载到闪存。
  - 手机上的实测数据。
  - Agent 场景的典型上下文长度，以及对应的 KV 占用估算。

### KT3（模型加载）

- 各推理框架的模型转换与加载方式：llama.cpp mmap、ExecuTorch、LiteRT、QNN context binary、Core ML、MNN、MindSpore Lite / HiAI Foundation。
- 权重 mmap 与 NPU 内存的关系：dma-buf、IOMMU 映射、长期 pin 带来的代价。
- 加载时间数据，UFS 4.x 的带宽。
- 量化后权重的可压缩性。

### S1、S2（性能跟踪与仿真）

- **云转端（S1）**
  - 端侧与云侧每 token 的能耗、时延、成本数据，以及厂商的云推理成本。
  - 端云协同与切分方法，例如路由、投机解码。
  - LLM / SoC 仿真器（LLMServingSim、Vidur、GenZ、LLMCompass 等，需核实）、手机功耗模型，以及真机校准方法（功耗轨、Perfetto）。
  - Agent 体验指标的定义。
- **并行化（S2）**
  - 方法：LLMCompiler、并行函数调用、投机工具调用、Skeleton-of-Thought。
  - 端侧 decode 受带宽限制时，合批能带来多少收益。

### G1、G3（3DGS 与神经渲染）

- **3DGS**
  - 移动端渲染：排序开销、免排序方法。
  - 压缩与格式（SPZ 等）、标准化（Khronos glTF、MPEG）、生成（单图前馈）。
  - 代表产品，以及手机端的帧率、内存数据。
- **神经渲染**
  - 硬件与图形 API：Apple A19 GPU 神经加速器与 MetalFX、Arm 神经技术与 Neural Super Sampling、Qualcomm 方案、Vulkan ML 扩展。
  - 神经纹理压缩，以及国内手机的插帧、超分方案。
  - 功耗与内存数据。

### G2、G4（AI 萌宠与生成式 UI）

- **AI 萌宠 / 虚拟伴侣**
  - 代表形态：Grok Companions、手机厂商的萌宠功能、AI 宠物硬件、虚拟宠物 App。
  - 技术栈：形象生成、动作生成、性格与记忆、常驻低功耗渲染。
  - 市场与留存数据。
- **生成式 UI**
  - 代表方案：Google、OpenAI（Apps SDK / MCP 相关）、Apple、HarmonyOS（卡片与元服务）等。
  - 对终端渲染引擎的要求：安全、性能、流式渲染。

## 4. 写作规则

- 每条关键事实给出来源 URL 和日期。来源优先级：官方文档 / 发布会、论文、内核文档与邮件列表、LWN、权威媒体。
- 数字必须有出处；没有出处的估算要写清计算过程，并标「估算」。
- 拿不准的标「待核实」；查不到就写「未找到公开资料」。**绝不编造产品名、版本号、数字或链接。**
- 区分各平台术语，不混用。
- 中文撰写；中文和数字之间不加空格。
- 观点鲜明：每部分末尾写「对立项的启示」，说清这条证据支撑我们的哪个技术点。
