# 第四部分 规划与投入

> 本部分回答以下问题：
> - 为什么现在投入；
> - 我们的差异化在哪里；
> - 2027 年如何安排；
> - 需要哪些投入；
> - 有哪些风险和需要决策的事项。
>
> 人力与预算的数字由团队补充，本文只给出结构，用占位符表示。2026-11-09 起按三项系统服务、13 项关键技术列示；投入只计新建部分，复用安全体系、由其他团队负责的会话级调度不计入。

## 4.1 为什么是现在：时间窗口

1.1.3 的业界进展表与 1.2 节的原型对比表显示，空白点正在以不同速度被填补。按速度分为四档：

| 分档 | 空白点 | 对我们的含义 |
|---|---|---|
| 已收敛，不宜正面竞争 | 模型作为系统服务；云端沙箱接口；凭证不进入沙箱 | 沿用业界形态，差异化放在记账和服务之间的接口上 |
| 正在被平台填补 | NPU 加载准入与模型级抢占（Android 17 NPU Manager）；系统模型的稀疏权重分层（Apple AFM 3）；系统托管的 GUI 自动化（Computer Control 预览） | 与平台对齐，不另起一套；差异化放在平台未覆盖的会话粒度、长上下文与新算力 |
| 窗口正在打开 | LPDDR-PIM：标准接近定稿，三星首个商用目标为 AI PC，手机尚无厂商表态；MoE 底座上手机（AFM 3 已量产） | PIM 已列入自研芯片规划，系统软件先行可形成软硬一体的先发优势；MoE 的专家命中率与模型结构选型是 2027 年的硬需求 |
| 长期空白 | 手机统一内存上的模型内存记账（含代分配归账）；MCP 与 A2A 的按调用权限判定；沙箱与内存的契约；手机侧的成本参数 | 长期建设，形成长期竞争优势 |

**判断**：2027 年是「会话级」能力与「新算力」的双重窗口期。平台已完成「模型级」能力；会话级的权限判定、内存分层与长上下文推理，在任何量产端侧系统中都尚未出现，但云端和学术已证明可行；PIM 等新算力的系统软件还是空白。

## 4.2 差异化论据

1. **商业价值可以折算。**
   - **推理**：重度 Agent 用户的云成本每年约 79–296 美元，端侧每多承接一成重度用户的 token，每 1000 万重度日活每年少付约 3 亿美元（估算，2.3.1）。
   - **沙箱**：交易类任务是端侧 Agent 唯一明确的变现路径，没有系统级权限管控就做不了（2.3.2）。
   - **内存**：每多出 1GB 等效可用内存，约等于每台省下 20 美元 DRAM（2.3.3）。
2. **软硬一体：PIM 已在自研芯片规划中。** 业界的 PIM 系统软件是空白，主流推理框架都不支持；我们可以与芯片团队联合定义系统接口，这是只做软件的平台方做不到的。
3. **我们聚焦「会话」层，平台聚焦「模型」层。** 三项系统服务都以 Agent 会话为单位，由同一个会话档位统一驱动，见第三部分 3.1.4 的联动表。
4. **模型内存的记账盲区在 Android 17 中仍未解决。** 限额只统计匿名页与 swap；dma-buf 的 memcg 计费仍停留在 RFC；共享服务代持的内存没有归属原语。先做可观测与代分配归账，是所有回收策略的前提。
5. **关键参数只能依靠建模与仿真获得。** 每 token 能耗、长上下文 prefill、切换与恢复时延、隔离开销、换出的写入代价，都找不到公开的手机实测。服务器上的结论在手机上会反转：服务器上重算优于换出，手机上换出快 31–215 倍。
6. **复用而不重做。** 沙箱复用安全体系的身份、密钥与证明，只新建执行管控层；记忆留在 Agent 层，不与 Agent 厂商争夺；投入集中在系统层独有的部分。

## 4.3 2027 年路线图（建议）

| 阶段 | 推理服务 | 执行沙箱 | 通用内存管理优化 | 推理服务内存管理 | 阶段验收 |
|---|---|---|---|---|---|
| **一季度 基线与可观测** | 3B 底座 8K–32K 的 prefill 与 decode 真机基线；选型准入卡与代价模型 | 进程级实例创建、冻结开销测量；AVF 可用性摸底 | 统一账本第一阶段：只记账、不限额；冷启动与换入基线测量 | 前缀命中率测量；专家缓存基线与路由轨迹采集 | 参考负载的关键参数全部获得真机值，替换第二部分的估算 |
| **二季度 机制原型** | 增量 prefill 与上下文裁剪；NPU 与 GPU 协同、带宽仲裁原型；NPU 在环评测平台 | 会话级进程实例；出站策略引擎与三维定档；出口代理（含 DNS） | 代分配归账；主动回收原型；SPE 预取与 .so 锁优化原型 | 三级前缀缓存树与带版本的缓存键；KV 块池与停放换出；专家多策略缓存；页对齐权重格式 | 单项指标达标：首 token、判定时延、KV 恢复、专家命中率 |
| **三季度 联动集成** | NPU 分块 prefill 与 KV 降精度；PIM 仿真平台与接口定义（联合芯片团队）；与模型团队完成 MoE 底座选型 | 冻结、快照、恢复接入档位事件；入站网关与数据标签贯通；凭证托管 | 按档位水线接入回收仲裁；档位事件预加载；冷热换出与意图预取 | 会话 KV 停放与恢复接入档位事件；专家与 KV 联合划分预算；NPU 零拷贝映射 | 3.1.4 联动表端到端跑通：切回 ≤1 秒、12GB 峰值不终止前台、注入路径全部拦截 |
| **四季度 全天回放与交付** | 32K 长任务全天回放；PIM 样片评估；UFS-PIM 冷专家卸载预研报告 | 虚拟机级隔离（按机型分级）；审计与策略回放 | 压力信号联动；全天回放验收 | 闪存写入预算；IO 优先级联调；全天回放验收 | 参考负载全天回放：各项指标全部验收；形成 2028 年规划 |

**2028 年及以后**：只预留接口，不进入 2027 年交付。

- PIM 正式接入（视自研芯片与 LPDDR6-PIM 标准进度）；UFS-PIM 冷专家卸载原型；
- 多 Agent 调用链；
- 基于注意力预测的升档；
- 广泛的虚拟机级隔离；
- 投机式端云解码。

## 4.5 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 平台方（Google）自行延伸到会话级 | 差异化收窄 | 与平台对齐接口，优先做平台不会做的部分：统一记账、沙箱与内存契约、PIM 系统软件、手机侧成本参数 |
| PIM 硬件与标准进度不确定 | 异构融合中的 PIM 部分推迟 | 2027 年交付物以 NPU 与 GPU 协同为主，PIM 以仿真与接口定义为主，不依赖样片按期到位 |
| 模型团队未采纳系统侧约束 | MoE 底座的 KV 或专家 IO 超出预算 | 选型准入卡作为准入流程的一部分；代价模型与 NPU 在环评测先行，用数据说话 |
| 芯片厂商 NPU 驱动不开放内存上报 | 记账存在盲区 | 经 NPU HAL 中介；尽早与芯片厂商对接 |
| 应用生态不接入 MCP 与 A2A | 沙箱的覆盖面受限 | 从系统应用和头部应用起步；接口对齐 App Intents、AppFunctions 的形态；沙箱只缓解风控与责任顾虑，商业原因靠商务合作 |
| 负载参数基于估算 | 目标值偏离 | 一季度用真机轨迹替换；本文所有估算都已标明公式与输入 |
| 闪存寿命 | 换出写入量过大 | 按恢复概率决定是否写出，并设日写入上限 |
| 沙箱自身被攻破 | 安全承诺失效 | 将注入语料与逃逸用例纳入持续集成的对抗性回归 |

## 4.6 需要决策的事项

1. **海外的 System Agent。** 海外机型的默认助手若是 Gemini，记忆的读取接口与 A2A 入口就不在我们手里。商业叙事与沙箱入站部分是否按国内、海外分开表述。
2. **GUI 后台虚拟屏是否纳入沙箱关键技术一。** 纳入则每个被操作的应用约多占 0.2–0.5GB（估算）。
3. **与安全团队、模型团队、自研芯片团队的协作方式。** 执行管控层由本项目新建、安全团队提供原语；模型结构寻优与模型团队联合；PIM 系统接口与芯片团队联合定义。
4. **会话档位与 11-03 排除项的关系。** 建议 2027 年只实现由确定性事件触发的「交互」与「后台」两档；基于注意力预测的升档列入 2028 年以后。
5. **人力与预算的数字（4.4）。**
6. **参考负载的真机数据**：团队已有的细粒度负载数据，可以直接替换第二部分的估算参数。
