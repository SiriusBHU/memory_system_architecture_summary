# AgentOS 内存管理子系统设计：统一记账底座与双策略域

**文档状态**：设计草案（v0.1）
**面向读者**：软件工程师、系统架构师
**日期**：2026-11-06
**关联文档**：《AgentOS 沙箱系统设计：从基础组件到关键技术》

## 1. 背景与动机

AgentOS 内存管理的核心冲突是：**一个常驻的大块头（模型与 Agent 运行时）与一群短命的交互进程（传统应用）争夺同一块 DRAM**。端侧设备内存预算为 8–16GB，而 Agent 负载的内存特征是传统移动内存管理从未面对的：GB 级模型权重常驻、随上下文线性增长的 KV cache、多会话并发、长时间驻留且无明显生命周期事件。

现有移动内存管理机制（Android LMKD、iOS Jetsam）在 Agent 场景下存在三处结构性不适配：

1. **记账主体错位**：按进程/应用记账，而 Agent 的一次任务横跨推理服务、沙箱实例、工具运行时等多个进程；
2. **QoS 目标失配**：隐含目标是"保前台应用不死"，而非"交互负载与 Agent 吞吐的双契约"；
3. **可见性缺失**：模型权重与 KV cache 走 dmabuf/DMA 路径，对传统内存管理近乎黑盒，压力判断失真。

## 2. 总体架构：一个底座，两个策略域

内存管理子系统**不是两个独立子系统，而是"统一记账与压力底座 + 两个策略域"**：

- **统一底座**：全量内存记账（含 dmabuf 可见性）与统一压力信号（扩展 PSI）。若模型内存对底座不可见，冷热判别将系统性失真。
- **域一：传统内存管理**。面向"Agent + 应用"叠加场景，核心职责是冷热判别与精准供给——既服务好 Agent，又保证传统应用的交互体验。
- **域二：模型内存管理**。作用于 DMA/dmabuf 路径，管理模型权重、KV cache、MoE 专家、LoRA 适配器等模型运行时对象。

设计原则两条：

1. **QoS 跟着用户注意力走，不跟着进程身份走**。Agent 并非天然是后台负载——当用户等待 Agent 回答时，该 Agent 会话即为交互负载，须临时升档。将 Agent 一刀切视为后台负载是最常见的设计错误。
2. **机制与策略分离**。OS 提供记账、压力信号、驱逐与分页机制；上下文内容选择、压缩与摘要策略归 Agent。

## 3. 域一：传统内存管理的改造

### 3.1 记账主体会话化

以**会话**为记账主体建立 memcg 层级：一个 Agent 会话聚合其推理服务调用、沙箱实例与工具进程的内存占用。精准供给的前提是供给对象可被计量。

### 3.2 QoS 双契约

- **交互类（保底供给）**：帧死线关键，映射 memcg `memory.min` 级别的硬保证；
- **Agent 类（弹性供给）**：吞吐导向、可延迟、优先回收，映射 `memory.low/high` 语义；
- **注意力感知升档**：当 Agent 任务进入用户等待路径（前台交互、实时语音），会话临时升入交互类；
- **压力分级回收**：以 PSI（Pressure Stall Information）分级驱动回收强度，替代单一 minfree 阈值。

### 3.3 冷热判别的三层语义

经典页级冷热（MGLRU、refault 距离）仍是基础，但 Agent 负载使"热"出现三个语义层：

| 层次 | 粒度 | 信号源 |
|---|---|---|
| 页热 | 4KB 页 | 访问位、refault 距离（历史信号） |
| 专家热 | MoE 专家 | router logits 预告（**未来信号**） |
| 会话热 | Agent 会话 | 会话活跃度、用户注意力状态 |

冷热判别须在三个粒度上同时进行，后两者的信号源在域二。

## 4. 域二：模型内存管理

### 4.1 作用范围

dmabuf/DMA 路径上的内存：dma-buf heaps（cached/uncached）、NPU 私有内存堆。现实约束是**厂商碎片化**——Qualcomm、MediaTek 的 NPU 内存模型各自为政，无统一抽象，域二需要一层厂商中立的 NPU 内存抽象（与推理框架子系统的 NPU HAL 共用）。

### 4.2 KV cache：纯缓存的驱逐经济学

KV cache 与经典匿名页有本质区别：**它是纯缓存，可由上下文重新计算再生**。驱逐不再只有"换出"一条路，一块冷 KV 有四种去向：

1. **换出到存储**（zRAM / UFS）；
2. **丢弃重算**（需要时按上下文重新 prefill）；
3. **溢出到云端**（端云协同推理时移交）；
4. **有损驱逐：摘要后写入记忆框架**——信息以语义形式保留，字节被回收。这是经典虚存不存在的路径，也是内存管理与记忆框架的连接点。

驱逐决策是在线成本模型：**重算成本（prefill FLOPs × 延迟）vs 换出成本（存储带宽 × 读回延迟）vs 信息损失（摘要）**的逐块权衡。

配套机制：

- **块化管理**：PagedAttention 式定长块，消除内部碎片，使驱逐粒度可控；
- **前缀共享**：多会话/多 Agent 共享 system prompt 的 KV 前缀，块级去重（RadixAttention 思路下沉到系统层）——端侧内存紧张场景下的净收益；
- **KV 量化与选择性驱逐**：冷 KV 降位宽（4bit/2bit），按注意力重要性选择性保留（H2O/SnapKV 类策略作为机制提供，策略选择归 Agent）。

### 4.3 MoE 专家管理：可预测的热

经典内存管理只有历史信号（LRU/refault）；MoE 的 router logits 会提前暴露下一 token 将激活的专家——**驱逐与预取第一次可以基于预告而非历史**：在上一个 token decode 的间隙预取下一专家。机制包括：

- **router 预告预取**：利用路由器的提前可见性隐藏存储读延迟；
- **专家驻留集合管理**：热专家常驻、冷专家分页，驻留集合随负载动态调整；
- **专家级压缩**：冷热专家采用不同位宽。

### 4.4 权重分页与 LoRA 热插拔

- **稠密权重分页**：层间访问模式差异巨大，支持层粒度/块粒度分页与按需加载；闪存直读权重（windowing + 批量读取）以压缩常驻集；
- **LoRA 适配器**：MB 级小对象、高频切换，独立驻留集合管理与热插拔，与大权重分离管理。

### 4.5 对 Agent 暴露的语义接口

域二对上暴露的不是页语义，而是**上下文预算**语义："上下文窗口即地址空间"——Agent 申请上下文预算，子系统决定预算内对象的驻留位置（DRAM / 存储 / 云端 / 摘要入库）。MemGPT 证明了这一抽象的可行性。

## 5. 两域接口

1. **统一记账**：dmabuf 纳入 memcg 可见性（上游内核已有 dmabuf 记账工作流，跟进或自研）；
2. **统一压力信号**：PSI 扩展模型内存维度——NPU 侧分配压力驱动传统侧回收，反之亦然；
3. **驱逐路径互通**：域二驱逐的"信息"流向记忆框架（摘要入库）；域一驱逐的"字节"流向 zRAM/存储；两套驱逐经济学在统一压力信号下调度。

## 6. 业界与学界洞察

### 6.1 业界现状

**系统侧**：

- **Android**：LMKD 以 oom_adj 进程优先级驱动回收；MGLRU（多代 LRU）已进入主线内核并在 Pixel 设备落地，显著改善冷热判别精度；PSI 用于压力感知；cgroup v2 的 memory.min/low/high/max 提供基础 QoS 语义。局限：记账主体仍是进程，dmabuf 可见性近年才由上游补丁补齐。
- **iOS**：Jetsam 以优先级带（priority bands）回收；内存压缩比例高、swap 策略保守；对第三方不开放任何调度接口。

**推理栈侧**：

- **vLLM**：PagedAttention 的工业实现；Sleep Mode 支持权重卸载与 KV 丢弃（RL 场景的权重热更新），验证了"权重与 KV 可被系统级换入换出"的工程价值。
- **SGLang**：RadixAttention 前缀树实现跨请求 KV 复用。
- **LMCache**：KV cache 作为独立缓存层外置，支持跨实例共享与存储分层。
- **Apple《LLM in a flash》**：闪存直读权重（窗口化 + 行列捆绑读取），证明权重常驻集可以远小于模型尺寸——权重分页的直接工业证据。
- **端侧推理框架**：llama.cpp / ExecuTorch / MNN / MLC 各自管理权重映射与 KV，均无系统级协同——多框架并存时内存被重复占用，正是"模型即系统服务"要解决的问题。
- **NPU 厂商**：Qualcomm AI Engine Direct、MediaTek NeuroPilot 的内存模型各自私有，无跨厂商抽象。

### 6.2 学界脉络

- **KV cache 管理**：PagedAttention（SOSP 2023）确立"KV 块化 = 虚拟内存"的范式；RadixAttention 解决跨请求前缀复用；H2O（NeurIPS 2023）、SnapKV、StreamingLLM 建立"重要性驱动的 KV 选择性保留"方向；KIVI、KVQuant 将 KV 压缩推到 2bit 量级。
- **MoE 内存优化**：EdgeMoE 提出专家粒度的端侧内存管理；MoE-Infinity、Mixtral-offloading 建立专家卸载与缓存方向；Pre-gated MoE 等工作验证 router 预测预取的可行性——"可预测的热"的学术基础。
- **端侧稀疏推理**：PowerInfer-2 实现手机上的神经元级冷热判别（热神经元驻留 NPU、冷神经元走 CPU），是"冷热判别下沉到模型结构内部"的代表作。
- **上下文即虚存**：MemGPT 将 LLM 上下文窗口显式建模为分页式虚存，长期记忆为外存，检索为缺页换入。
- **卸载谱系**：FlexGen、ZeRO 系列建立 GPU↔CPU↔存储的多级卸载框架，端侧可借鉴其成本模型。
- **系统内核**：MGLRU（Google）解决传统 LRU 的精度与锁竞争问题；dmabuf memcg 记账上游补丁使 DMA 内存首次可被纳入统一回收。

**洞察总结**：学界的四个方向（KV 块化与压缩、MoE 专家管理、神经元/层粒度的冷热判别、上下文虚存化）与业界的两个事实（dmabuf 可见性补齐、闪存直读权重）共同指向同一结论——**模型内存已经可以被系统性管理，缺的是把这些点状技术收编为 OS 级机制的那一层**。这正是域二的定位。

## 7. 挑战与关键技术

| # | 挑战 | 关键技术 |
|---|---|---|
| M1 | 模型内存对传统内存管理不可见 | dmabuf memcg 记账；PSI 扩展 DMA 压力维度；统一内存水位视图 |
| M2 | 记账主体错位（进程 ≠ 会话） | 会话级 memcg 层级；跨进程聚合记账（推理服务/沙箱/工具进程归属同一会话） |
| M3 | 双契约精准供给 | memory.min/low/high/max 语义改造；注意力感知升档（用户等待路径检测）；PSI 分级回收 |
| M4 | KV 驱逐的在线成本决策 | 块化管理（PagedAttention）；重算成本 vs 换出读回成本的在线模型；前缀共享去重；冷 KV 量化 |
| M5 | MoE 专家冷热 | router 预告预取（decode 间隙隐藏读延迟）；专家驻留集合动态调整；冷热专家分级量化 |
| M6 | 稠密权重与 LoRA | 层/块粒度权重分页；闪存直读（窗口化 + 批量读）；LoRA 驻留集合与热插拔 |
| M7 | 端侧存储约束 | zRAM vs UFS 的换出选择；写放大控制；闪存寿命预算（换写总量限额） |
| M8 | NPU 内存抽象碎片化 | 厂商中立 NPU 内存抽象层（与推理框架 HAL 共用）；dmabuf heap 统一封装 |
| M9 | KV 共享与沙箱隔离的张力 | 前缀共享限定同信任域；共享块打 ACL 标签；跨域共享回退为各自持有——与沙箱子系统的接口面联动 |

M9 是架构交叉点：前缀共享的收益建立在"多会话共享 KV"之上，而沙箱的存在恰恰意味着会话分属不同信任域——**共享去重与隔离保证之间存在真实张力**，必须在两子系统的接口上显式处理，不能各自为政。

## 8. 与负载建模、系统仿真的结合

本子系统与负载建模/仿真方向的耦合比沙箱更直接：

- **负载模型是策略输入**：冷热判别与供给策略的效果完全取决于负载特征——token 到达模式、会话并发模型、任务长度分布、专家激活分布。这些正是负载建模的输出产物。
- **仿真是策略验证场**：回收策略、驻留集合大小、预取窗口等参数对交互帧率、Agent TTFT（首 token 延迟）、重算率的影响，只能在仿真中大规模扫描。内存压力场景的回放（真实 trace 驱动）是仿真平台继沙箱验证之后的第二个落地场景。
- **核心指标**：交互帧率（应用体验保障线）、TTFT 与 decode 吞吐（Agent 体验线）、KV 重算率、refault rate、专家预取命中率。
- **立项表述**："负载模型驱动的内存策略设计与验证"，与沙箱方向的"覆盖率驱动的接口设计"形成对仗。

## 9. 落地路线

| 阶段 | 内容 | 产出 |
|---|---|---|
| P0 | 统一记账底座：dmabuf memcg 记账 + 会话级 memcg + PSI 扩展 | 全量内存可见性（M1、M2） |
| P1 | KV 块化与驱逐成本模型；QoS 双契约与注意力升档 | Agent 吞吐与交互体验双达标（M3、M4） |
| P2 | MoE 专家管理、权重分页与 LoRA 驻留 | 模型常驻成本下降（M5、M6） |

## 10. 开放问题

1. **重算 vs 换出的在线决策校准**：成本模型参数随芯片、存储、模型变化，如何自动标定；
2. **有损驱逐的保真度**：摘要入库后的信息损失如何度量，Agent 如何感知"这段上下文已被摘要"；
3. **KV 共享的信任域边界**：跨域前缀共享的信息流风险的形式化刻画；
4. **NPU 内存抽象的标准化**：厂商碎片化下抽象层的最低公共能力集是什么；
5. **注意力升档的判定**：如何可靠检测"用户正在等待 Agent"而不被滥用（Agent 自我升档的博弈问题）。
