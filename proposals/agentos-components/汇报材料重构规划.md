## 一、故事主线

手机正在从「人操作 App」变成「Agent 代人操作」。

今天 OS 的四大件都是为「人 + App」设计的：调度、进程隔离、文件系统、虚拟内存。到了「常驻模型 + 代理执行 + 长期记忆」的负载下，这四件各自都不够用。

Agent OS 要把它们重构为四个系统服务：推理、沙箱、记忆、内存管理。2027 年我们投入 X 人，做 N 项关键技术，达成可量化的目标。

| 经典 OS 部件 | Agent OS 组件 | 为什么绕不过去 |
|---|---|---|
| 调度器 | 推理 | 一个底座模型要服务全系统的多个会话，必须有人分配算力、决定抢占 |
| 进程隔离 / 保护环 | 沙箱 | Agent 以用户身份、在不可信输入下代为执行，必须有人划定能做什么、出了事能否收回 |
| 文件系统 | 记忆 | 跨 App、跨会话的个人上下文，必须有人统一存、取、授权、遗忘 |
| 虚拟内存 | 内存管理 | GB 级模型内存常驻，并与 App 争夺 DRAM，必须有人记账、回收、协调共存 |

这个类比是回答「为什么是这四个、为什么绕不过去」的最短路径。领导不需要先懂 Agent，只要认同「OS 必须有调度、隔离、存储、内存」。

## 四、四组件关键技术初稿（待你修改）

### 推理（≈ 调度器）

**系统角色**：把一个底座模型变成全系统共享的推理服务，按会话分配算力。

1. **会话级调度与抢占**：调度跨 CPU / GPU / NPU。参照：Android 17 NPU Manager 只做到模型级卸载。
2. **KV / 前缀复用与多适配器驻留**：缓存键包含底座版本、适配器版本和数据标签。
3. **端云路由**：按数据标签、时延、电量决定在哪里推理。

### 沙箱（≈ 进程隔离 / 保护环）

**系统角色**：Agent 以用户身份、在不可信输入下代为执行；系统要保证出了事也出不了圈。

1. **会话级隔离与状态底座**：进程级 / AVF pVM 分级隔离，加快照与可逆性分级。
2. **策略引擎与数据标签流**：按外部性、可逆性、敏感度三维定档，数据标签跨会话持久。
3. **出口代理与凭证经纪**：覆盖包括 DNS 在内的全部出口，由系统持钥、代为请求。

### 记忆（≈ 文件系统）

**系统角色**：跨 App、跨会话的个人上下文，由系统统一存、取、授权、遗忘。

1. **端侧分层记忆存储与检索**：分工作 / 情景 / 语义三层，在功耗与内存预算内建向量索引。
2. **写入治理**：包括来源与完整性标签、摘要入库检查点、约束钉住。
3. **系统级个人语义索引与第三方授权**：规定谁能读哪类记忆，以及读到后数据怎么流。

### 内存管理（≈ 虚拟内存）

**系统角色**：让模型内存成为可记账、可回收、能与 App 共存的一等公民。

1. **统一记账底座**：dma-buf / GPU / NPU 内存的归属，以及代分配归账。
2. **模型内存分层回收**：KV 分层与压缩；稀疏权重按请求工作集换入，参照 Apple AFM 3 Core Advanced。
3. **应用内存智能化**：.so 文件页锁，以及基于 SPE 冷热识别的预取与换出。
4. **模型加载 IO 与零拷贝**。

内存管理的第 3、4 项，以及第 2 项的一部分，直接沿用 2027 立项的 KT1–KT3。

## 七、第三版调整（2026-11-09）

> 依据：你与专家通读 49 页 PPT 后的意见，以及此前关于沙箱定位、记忆归属、推理与推理内存清单的三轮讨论。

### 7.1 两项整体调整

**1. 系统服务收为三项，记忆移出 OS。**

Agent 需要的底层能力只有两项：推理和执行，分别对应推理服务、执行与沙箱。Agent 叠加在用户正在使用的应用之上，二者共用同一块芯片和同一块内存，因此还需要内存与资源管理来协调前台 Agent 与应用。

| 系统服务 | 回答的问题 | 内含模块 |
|---|---|---|
| 推理服务 | Agent 怎么想得快、想得起 | 推理服务的优化 |
| 执行与沙箱 | Agent 怎么安全地做事 | 执行沙箱 |
| 内存与资源 | Agent 与应用怎么共存 | 通用内存管理优化、推理服务内存管理 |

记忆分为两部分，都放在 Agent 层：

- **记忆本体**：各 Agent 各自持有。System Agent 有自己的记忆，微信、抖音等应用的 Agent 也有各自的记忆。
- **记忆的读取权限**：作为 System Agent 的一项能力，以 MCP 或 A2A 协议提供给其他 Agent；每次读取由执行沙箱判定权限。

**2. 每个领域的论证链补上体验与商业化问题。**

逻辑链改为：复杂场景与负载 → 用户体验与商业化问题 → 技术瓶颈 → 关键技术。

| 领域 | 体验与商业化问题 |
|---|---|
| 推理服务 | 推理需求高速增长，云端成本已经很高，很多公司在评估云转端的可行性与风险；核心矛盾是成本与体验之间的取舍 |
| 执行与沙箱 | 要做 MCP 与 A2A，必须有系统级的权限管控：外部 Agent 经 A2A 访问系统能力与数据，Agent 经 MCP 调用外部工具，两个方向都需要沙箱 |
| 内存与资源 | 沿用 2027 立项已有材料：叠加场景下的冷启动、切换卡顿与后台被杀 |

### 7.2 关键技术清单（共 13 项）

| 系统服务 | 模块 | 关键技术 |

| 推理服务 | 推理服务的优化 | 1. Agent 超长序列推理的优化<br>2. LPDDR-PIM、NPU、UFS-PIM 异构融合计算（PIM 已列入自研芯片规划）<br>3. 硬件亲和的模型架构寻优 |
| 执行与沙箱 | 执行沙箱 | 1. 会话级隔离与状态底座<br>2. MCP / A2A 调用的权限判定与数据标签<br>3. 出口代理与凭证托管（范围收窄：密钥存储复用安全体系） |
| 内存与资源 | 通用内存管理优化（不变） | 1. 会话级记账与 memcg 水线自适应<br>2. 系统服务与常驻进程的主动回收<br>3. 匿名页冷热识别与预取换出 |
