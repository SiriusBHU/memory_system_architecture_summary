## 讲述主线

每一部分回答上一部分留下的问题：

1. **洞察**：
   - 业界在往哪走；
   - 端侧 Agent OS 应该具备什么形态；
   - 为什么是这四个组件。
2. **场景与负载**：用「贴身秘书」这一个参考负载，把四个组件的需求量化出来。之后每个瓶颈、每个目标都引用这里的数字。
3. **缺口与瓶颈**：当前手机操作系统在这些数字下哪里不达标，原因是什么。
4. **架构与关键技术**：
   - 用「会话」这一个对象把四个组件串起来；
   - 每个瓶颈对应一项关键技术，每项技术的目标回扣负载数字；
   - 内存管理分为两个模块：通用内存管理优化、模型内存管理。
5. **规划与投入**：为什么是现在、如何安排、需要多少投入。

## 关键技术单页的统一结构（solution-kickoff-difficulties）

- **标题**：技术名 + 后半句，后半句写技术路线与核心量化目标。
- **左上「挑战 / 目标」卡**：
  - 挑战写清对应的负载需求、现有机制为何不足、量化代价；
  - 目标写成可验收的量化指标（建议值）。
- **左下方案架构**：分三个编号分区（感知与建模 → 决策 → 执行与作用），节点写「对象 + 动作」，并以评估结果回流形成闭环。
- **右侧三个技术难题**：每个难题写「难点」与「方法」，关键突破用蓝色加粗；难题编号与架构分区编号对应。
- **右下交付节奏**：三个里程碑，取自 2027 年路线图的季度安排。

## 构建方式

```
cd /d/projects/ppt_templates && uv run python <本目录>/build.py --preview
```

- **`pages.py`**：各类页面的生成函数，包括 kt_page、arch_page、load_page 和瓶颈页部件；
- **`lib.py`**：绘图原语与配色；
- **`p*.py`**：各页内容，按汇报顺序登记在 `build.py` 的 `MODULES` 中。
