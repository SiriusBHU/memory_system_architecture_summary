## §0 摘要

1. **记忆正在「文件系统化」，这对「记忆 ≈ 文件系统」的类比是强支持。** Anthropic memory tool 就是客户端文件目录 [E11]，Letta 在 2026-02 把记忆块改成 git 管理的文件 [E24]，Manus 把文件系统当外部记忆 [E15]，OpenViking 用目录范式组织上下文 [E30]。Letta 的纯文件基线在 LoCoMo 上得 74.0%，高于 Mem0 当时自报的 68.5%（厂商自测）[E6]。
2. **但 OS 能发力的不是索引结构，而是元数据和授权。** 写入决策几乎全由 Agent 或框架里的模型完成，没有一家交给 OS [E6][E7][E11][E22]；在 MemoryAgentBench 上，检索结构（向量、图）也不稳定优于简单方案 [E2]。判断：OS 应提供「inode + 扩展属性（来源、完整性、数据域）+ 审计日志 + 快照回滚 + 级联删除」，不要把向量或图写死进接口。
3. **记忆是持久化注入的载体，所以 ACL 必须管写。** MINJA 只靠查询交互就能注入记忆，注入成功率 98.2%（理想条件）[R25]；PoisonedRAG 每个目标问题只需 5 条恶意文本，攻击成功率约 90% [R27]；ChatGPT 与 Gemini 都有真实的记忆注入演示 [R29]。2026 年的防御预印本一致认为内容检测不可靠，来源绑定加隔离区更有希望 [R30]。
4. **「跨链不升级」需要延伸到时间维度。** 低完整性会话写入的记忆，在后续会话里被读出时仍应是低完整性数据。判断：记忆框架是信息流标签跨会话持久化的唯一位置，这是记忆与沙箱之间最重要的接缝（J4）。
5. **J1（KV 有损驱逐 → 摘要入库）在学术上是空白，且摘要质量没有保障。** 没有找到把两者做成同一路径的系统研究 [E26]；Factory 的压缩评测中，压缩率 98.6%–99.3% 时质量只有 3.35–3.70 分（满分 5），「碰过哪些文件」这类结构化状态丢得最多 [E12]；简单的观察遮蔽成本减半，解决率不输 LLM 摘要 [E14]。
6. **个人语义索引确实是空白，但空白要表述准确。** 三星 PDE（只服务三星原生应用）[R11]、Windows Recall [R1]、Pixel Magic Cue [R9] 都不向第三方开放；Apple 的 IndexedEntity + Core Spotlight 是唯一有文档的第三方 donation 入口 [R13]，但 Siri 个人上下文的上线状态无法确认 [R14][R15]。空白在于「开放、查询时授权、跨应用、来源可追溯」四者同时满足。
7. **Recall 的教训是「存储安全做对了，使用安全没做完」。** 2026 年的 TotalRecall Reloaded 没有攻破 enclave，而是在 Windows Hello 认证后，从接收解密结果的 UI 进程里取走数据；微软称这是设计内行为 [R5][R7]。判断：ACL 的主体必须包含结果的接收进程，结果返回路径也要受约束。
8. **基准分不能用来选型。** 同一系统在 LoCoMo 上有 58%–84% 多种说法 [E5]；LoCoMo 被审计出约 6.4% 的答案键有误 [E10]；冲突消解（新事实覆盖旧事实）是所有方法的共同短板，MemoryAgentBench 多跳场景下所有方法都不超过约 7% [E2]。判断：OS 应度量自己能控制的变量（来源覆盖、删除完备性、查询延迟与能耗、索引体积），而不是复刻榜单。
9. **端侧索引的资源成本几乎是盲区（J7）。** 硬数据只有 EmbeddingGemma（308M 参数，量化后 RAM 低于 200MB）[R34] 和 Recall 的存储配额 [R3][R4]。按本文估算，50 万条个人实体若用 768 维 float32 存储，仅向量就要约 1.5GB，截断到 256 维并做 int8 量化后约 130MB。维度截断和量化在端侧是必选项。
10. **立场结论**：MEM-1 需修订（OS 托管机制与元数据，不托管索引结构）；MEM-2 支持（补写入授权与删除保证）；MEM-3 需修订（只在文本层做，必须可逆；KV 层不做摘要入库）；MEM-4 支持但需重新表述（四要素同时满足，补排除权与受约束返回）。

## §3 逐问题分析

### Q1 Agent 记忆系统格局：写入决策由谁做

按「谁决定写什么」，2025H2 至 2026 年的格局可以分成四类：

| 写入决策方 | 代表 | 机制 | 证据 |
|---|---|---|---|
| Agent 自己 | Letta、Anthropic memory tool、Manus | LLM 调用文件或记忆块工具读写；Letta 每个子 Agent 一个 git worktree，靠合并解决并发写 | [E11][E15][E24] |
| 框架抽取器 | Mem0、Zep / Graphiti | 摄入时由另一个模型抽取事实或构图；Mem0 新算法只加不删 | [E4][E7] |
| 产品系统 | ChatGPT、Claude、Gemini | 模型判定加用户显式指令；用户可见、可删；Claude 按项目隔离 | [E27] |
| 学习出来的策略 | Memory-R1 | RL 训练记忆管理器 | [E22] |

**数据与分歧。** Letta 用文件工具在 LoCoMo 上拿到 74.0%，它的解释是「能否记住，取决于 Agent 是否知道何时、如何调用检索，而不是检索机制本身」[E6]。但同一时期，以 GPT-4o-mini 为主干的商业记忆系统在 MemoryAgentBench 上全面低于长上下文 Agent；MIRIX 把主干换成 GPT-4.1-mini 后，总分从 26.2 升到 37.7 [E2]。两组数据放在一起，唯一稳妥的结论是：**主干模型和评测配置对得分的影响，大于记忆架构本身。**

**这说明什么。** 判断：写入策略本身不是 OS 的发力点，业界已经把它交给模型。OS 有话语权的是策略之外的三件事：

- 谁有权写；
- 写入时打什么来源标签；
- 删除能否真正触达所有副本。

这正好对应「机制归 OS、策略归 Agent」的经典划分，MEM-2 的方向是对的。

### Q2 记忆评测与失效模式

**基准本身的问题。**

- LoCoMo 只有约 20K token，LongMemEval-S 约 103K token，全上下文基线就能覆盖，记忆系统的真实收益被掩盖 [E9]。
- 评委提示一换，排名就变 [E9]。
- LoCoMo 被审计出约 6.4% 的答案键有误（审计方是竞争厂商）[E10]。
- 厂商把自己的研究页当成数值的最终解释者（Mem0：「若线上发现多个数值，以本页为准」）[E7]。

**失效模式。**

- **冲突消解**：最严重的短板。单跳尚可（GPT-4o 60.0），多跳全面崩溃（所有方法不超过约 7%）[E2]。Mem0 新算法选择只加不删，把冲突留给检索阶段，过时事实会一直留在存储里 [E7]。
- **经验遵循**：劣质记录被检索后会被放大；「严格添加 + 选择性删除」平均带来约 10% 的绝对提升 [E25]。这与 Mem0 的工业选择相反，是一个真实的分歧。
- **长上下文退化**：输入变长后，语义相似的干扰项会加剧退化 [E16]。
- **参数化记忆**：文档与预训练知识冲突时，Doc-to-LoRA 类方法系统性失败，报告案例的准确率为 46.4% [E21]。

**这说明什么。** 判断：选型不能看榜单。OS 应该建立自己的评测口径，只度量 OS 能控制的变量：

- 写入来源覆盖率；
- 删除完备性（原文、向量、图、摘要、缓存、导出副本是否都删到）；
- 查询延迟与能耗；
- 索引体积。

这些变量正好可以用本部门的负载建模与仿真方法先建立基线。

### Q3 端侧个人数据索引

**三条商业路线。**

1. **capture 路线（Windows Recall）**：公开资料中安全工程最透明的一例。
   - 2024-09 重设计后：默认关闭，Windows Hello 门控，快照和向量库放进 VBS enclave，每个快照单独加密，密钥由 TPM 保护 [R1]。
   - 2026-03 的 TotalRecall Reloaded 没有攻破 enclave，而是向接收解密结果的 AIXHost 进程注入 DLL，在 Hello 认证后取走数据；微软称这是设计内行为 [R5][R7]。
   - 另一个结构性问题：被采集的应用没有话语权，Signal、Brave 等只能自己去阻止截屏（单一来源，待核实）。
2. **donation 路线（Apple）**：应用把实体类型声明为 `IndexedEntity`，即可进入 Core Spotlight 的词法和语义检索 [R13]。这是唯一有文档的第三方入口，授权单位是应用声明的实体。但 Siri 个人上下文在 2026-02 被报道推迟到 iOS 26.5 或 iOS 27 [R14][R15]，实际上线范围无法确认。
3. **封闭自建路线**：
   - 三星 PDE 把知识图谱放在 Knox Vault，明确只服务三星原生应用 [R11][R12]；
   - Pixel Magic Cue 汇集 Google 自家应用的数据，2025-11 起由 Private AI Compute 做云侧增强 [R8][R9]；
   - 华为小艺记忆有记忆主页，开发者侧有 Data Augmentation Kit 构建应用知识库，但不是系统级跨应用索引 [R18][R19]。

**donation 与 capture 的取舍。**

| 维度 | donation | capture |
|---|---|---|
| 覆盖 | 只限接入的应用，随生态增长 | 屏幕可见的一切 |
| 结构化程度 | 高（实体 schema） | 低（OCR 文本、像素） |
| 授权粒度 | 可到实体类型 | 一般只有功能开关加过滤规则 |
| 被采集方话语权 | 有 | 无 |
| 防投毒 | 来源明确 | 任何网页文字都能进入索引 |
| 冷启动 | 慢，需要应用适配 | 快 |

判断：OS 方案应以 donation 为主路径，capture 只作为受限兜底——用户逐应用、逐场景开启，被采集应用有排除权，只保留文本和向量、不保留原图。

**Picker 式授权的边界。** Android 14 的部分媒体访问和 Photo Picker 说明，「由 OS 渲染选择器、应用拿不到未选条目」的模型已经成熟 [R36]。但它解决的是「读一批具体对象」，不是「Agent 对整个索引做开放式语义查询」。后者需要**查询时授权**（按任务和数据域授权），现有先例都不覆盖。Gemini Personal Intelligence 的授权单位是「应用级连接」[R17]，也到不了这个粒度。

**情境完整性研究的定位。** AirGapAgent、PrivacyLens、AgentDAM 把隐私判断放在模型里或模型前的过滤器里。它们能把泄露率从三成多降到个位数 [R22][R24]，但输出是概率性的。判断：ACL 做硬边界（谁能读哪个数据域），情境完整性做软边界（同一数据域内，这次披露是否适合当前任务），两者分层并存。

**这说明什么。** MEM-4 的「最大生态空白」成立，但必须表述准确：没有任何一家同时做到「向第三方 Agent 开放、查询时授权、跨应用、来源可追溯」。只说「没人做个人索引」是错的。

### Q4 记忆压缩与遗忘

| 方法 | 数据 | 局限 | 证据 |
|---|---|---|---|
| Anthropic context editing | 100 轮搜索任务 token 降 84%；与 memory tool 合用，相对基线 +39% | 基线与指标未公开 | [E11] B |
| 观察遮蔽 | 成本减半，解决率不降 | 只在 SWE-agent 上验证 | [E14] A |
| ACON | 峰值 token 降 26%–54% | 需要学习压缩准则 | [E13] A |
| Factory 锚定摘要 | 压缩率约 99%，质量 3.70 / 5 | 厂商自评，自己的方法参赛 | [E12] B |
| LLMLingua-2 | 2–5 倍压缩，F1 87.8→86.9 | 高压缩比下没有可靠数据 | [E29] A / C |

规律很清楚：**清除旧观察是性价比最高的压缩；LLM 摘要的边际收益不稳定，而且最容易丢结构化状态。** Manus 的原则是压缩必须可逆——网页内容可以丢，URL 必须留 [E15]。

**遗忘。** 工业界偏向「不删，靠检索排序淘汰」（Mem0 只加不删 [E7]、MemoryOS 靠 Heat 衰减）；学术界证明选择性删除有收益 [E25]。重复压缩的累积损失几乎无人度量 [E26]。

**记忆格式迁移。** 2026-03 Gemini 提供了记忆导入功能，第一次出现产品级的迁移需求，但格式是自然语言文本，没有跨厂商 schema 标准 [E27]。嵌入模型换代会让向量索引整体失效，这一点没有找到量化研究。

### Q5 隐私与合规

| 技术 | 落地实例 | 保护对象 | 局限 |
|---|---|---|---|
| 设备侧硬件隔离存储 | Knox Vault（PDE）[R12]；VBS enclave + TPM（Recall）[R1] | 静态数据与密钥 | 解密后的使用路径是新边界 |
| 隔离计算域 | Android Private Compute Core [R10] | 处理中的数据与网络出口 | 官方资料停在 2021 年 |
| 云侧机密计算 | Google Private AI Compute [R8]；Apple PCC、Meta Private Processing（见 C1） | 上云时的数据 | 信任根仍是厂商 |
| 联邦学习 / 分析 | Private Compute Services [R10] | 模型改进 | 与索引检索本身无关 |
| 差分隐私 | 未找到个人索引场景的落地资料 | — | — |

判断：个人索引的主力隐私技术是「设备侧 TEE + 数据不出端」，差分隐私和联邦学习服务于模型改进，不是索引本身。

**合规。** EDPB Opinion 28/2024 认为训练过个人数据的模型不能一概视为匿名 [R33]。端侧记忆索引是外置存储，删除比删模型参数容易，但前提是派生物可追溯。判断：删除必须设计成一等原语，覆盖原文、向量、图、摘要、缓存、导出副本六类副本。任何摘要或派生物都要能追溯到来源记录，否则删除权无法兑现。中国 PIPL 第 47 条（删除权）、EU AI Act 的原文本轮未核实。

**可见、可删、可导出。** 商业产品普遍做到了条目级可见和可删；可导出与来源可追溯最弱 [R38]。来源可追溯同时服务合规（追溯派生物）和防投毒（回溯污染源），应作为 OS 记忆层的基础字段。

**多 Agent 共享。**

| 系统 | 共享单位 | 读写区分 | 冲突处理 | 溯源 |
|---|---|---|---|---|
| Letta shared blocks | 整块挂到多个 Agent | 只能整块设只读 | last-write-wins（官方列为反模式） | 无 |
| Mem0 | user / agent / app / run 标识 | 由过滤条件表达 | 单一主实体 | 无 |
| LangGraph store | 命名空间元组 | 命名空间即隔离 | 取决于后端 | 无 |
| Collaborative Memory（学术） | 私有碎片 + 选择性共享碎片 | 读写双策略 | — | 不可变溯源 |

来源：[R31][R32]。工业框架的隔离都是「命名空间 = 租户」，没有「按来源数据域授权」。

### Q6 与推理的耦合

- **KV 作为记忆**：Cartridges 是最强论据（内存降 38.6 倍）[E17]，但需要离线训练，不适合频繁更新的个人记忆。CacheBlend / LMCache 解决的是「已有文本的 KV 复用」，不是「新写入的记忆」[E19]。
- **检索式注意力**：InfLLM、RetrievalAttention 要求内存里保留完整 KV 或其索引 [E20]，在手机上不成立。
- **参数化记忆**：L1 成熟度，无法精确遗忘单条事实，与预训练知识冲突时会失败 [E21]。
- **有损驱逐 → 摘要入库**：没有找到系统研究。最接近的 IndexMem 是把被驱逐的 KV 压成潜在向量回灌注意力，不是文本入库 [E26]。

**这说明什么。** 判断：KV 适合做「由 OS 管理的缓存」（可丢弃、可重建、归内存管理记账），不适合做「系统的记录」（需要可解释、可删除、可迁移）。记忆框架托管的应该是文本 / 文件对象及其派生索引；KV 和适配器留在模型内存域。

### Q7 记忆安全（J4）

| 攻击 | 注入方式 | 持久化位置 | 要点 | 证据 |
|---|---|---|---|---|
| AgentPoison | 向 RAG / 记忆库植入触发式后门文档 | 向量库 | 无需微调模型 | [R26] C |
| MINJA | 只通过查询交互注入，不直接写记忆 | Agent 记忆库 | 注入成功率 98.2%（理想条件） | [R25] A / C |
| PoisonedRAG | 向知识库注入少量文本 | 知识库 | 5 条文本即可达约 90% | [R27] A |
| MemoryGraft | 在 README 等文件里植入「成功经验」 | 经验检索池 | 持久化，直到人工清除 | [R28] C |
| ChatGPT 记忆注入（spAIware） | 不可信文档或网页触发记忆写入 | 产品记忆 | 跨会话持久化并外泄 | [R29] C |
| Gemini 延迟工具调用 | 文档里埋下「当用户说 X 时调用工具」 | 长期记忆 | 绕过「解析文档时不执行」 | [R29] C |

**共同机理**：

- 记忆把一次性的间接注入变成了持久化注入；
- 写入通道往往不做权限检查，因为「记住」被当作 Agent 的内部行为；
- 检索时，恶意记录与可信记录混在一起，没有来源区分。

**防护方向**：2026 年的预印本 [R30] 显示，信任分数和内容清洗的阈值难以校准；写入时绑定来源、佐证后再提升，作者自评可把「重洗」攻击的成功率从最高 68% 降到 0%；Memory Sandbox 从工具层移除召回能力，九个模型中八个的攻击成功率降到 0%，但有一个推理模型反而升到 100%。

判断：稳健的方向是结构性控制，而不是内容检测。OS 记忆层需要提供：

1. **不可伪造的来源标签**：写入者身份、会话、数据域、该会话是否接触过不可信内容（完整性等级）。
2. **写入授权与隔离区**：接触过不可信内容（网页、邮件、第三方工具返回）的会话，写记忆需要用户确认或先进入隔离区；隔离区的记忆不进入高权限动作的上下文。
3. **读取时降级**：低完整性主体写入的记忆，读出时仍按低完整性数据对待。这把沙箱的「跨链不升级」（SBX-7）从调用链延伸到了时间维度。
4. **快照与回滚**：发现污染后可以按来源批量撤销，这对应沙箱七要素里的 undo。

### Q8 端侧索引的资源成本（J7）

- **嵌入模型**：EmbeddingGemma 量化后 RAM 低于 200MB [R34]，这是唯一明确的端侧数据点。在 16GB 机型上常驻尚可；在 8GB 机型上与模型 KV 竞争时，应作为可回收的模型内存，按事件加载、空闲驱逐。
- **索引体积**（估算）：50 万条实体在 768 维 float32 下仅向量就约 1.5GB；截到 256 维并做 int8 量化后约 130MB。原文、OCR 文本和元数据往往比向量更大；Recall 的配额（25GB 约存三个月）说明 capture 路线的存储主要被原始快照占据 [R3][R4]。
- **建索引能耗**：没有找到手机上的公开数据。Recall 要求 40 TOPS NPU [R2]，说明微软认为后台建索引需要专用 NPU 才能控制功耗（判断）。端侧做法应是充电且空闲时批量建索引，增量更新按事件触发。
- **存储引擎**：ObjectBox 4.0 自称首个端侧向量数据库（HNSW），但没有公开基准 [R35]；HarmonyOS 关系型数据库有向量能力（第三方文章，C）[R20]；sqlite-vec 未查到移动端数据。HNSW 的随机访问对 UFS 不友好，规模大时 IVF / PQ 类可能更省内存，需要仿真或真机验证。

**这说明什么。** J7 是公开资料的盲区。这既是立项机会——可以用负载建模与仿真先建立基线；也是风险——如果拿不出成本模型，就无法证明「OS 常驻统一索引」是合理的。

## §4 趋势判断

**正在收敛的方向**

1. **记忆的文件化**：Agent 用文件工具管理记忆，需要时再叠加索引。
2. **记忆可见、可编辑、按作用域隔离**：已是商业助手的标配。
3. **个人数据索引本地加密、默认关闭、可删除**：Recall、PDE、Gemini PI 都是如此。
4. **上云兜底用远程证明的机密计算**：PCC、Private AI Compute。
5. **防投毒收敛到「来源绑定 + 写入控制」**，而不是内容检测。

**公认的空白点**

1. 面向第三方 Agent、查询时授权的统一个人语义索引接口。
2. 被采集方的排除权。
3. 条目级来源标签与跨副本级联删除。
4. 冲突消解（新事实覆盖旧事实）。
5. 记忆格式的跨厂商迁移标准。
6. 端侧资源成本基准（体积、能耗、延迟）。
7. KV 驱逐与长期记忆写入的联合研究（J1）。

**仍有分歧的问题**

1. 删不删：学术界说选择性删除有收益，Mem0 的工业选择是只加不删。
2. 图记忆值不值：Zep 有时间推理优势，但纯文本方案的分数更高。
3. 摘要还是遮蔽：Factory 主张结构化摘要，JetBrains 主张遮蔽。
4. capture 与 donation 谁做主路径。
5. 个人上下文放端侧还是云：Gemini PI 用云账户数据，Apple / 三星 / Pixel 强调端侧，华为强调端云协同。

### 5.2 修订后的立场表述（建议稿）

- **MEM-1′** OS 提供记忆对象存储，文本 / 文件为一等形态，向量与图为可选的系统索引服务。每个对象携带来源、完整性等级、数据域、版本四类元数据。OS 提供读写双向 ACL、审计日志、快照回滚和跨副本级联删除；索引结构由 Agent 或框架决定。共享按标签交集授权。
- **MEM-2′** 「记什么、忘什么、何时检索」归 Agent；「能不能写、打什么标签、删除能否触达、配额多少」归 OS。
- **MEM-3′** 有损驱逐接口只开在上下文文本层。被驱逐的已决议内容可以写摘要入库，摘要必须带原文指针；KV 层的驱逐由内存管理按成本模型处理，不经过记忆框架。
- **MEM-4′** 端侧个人语义索引的空白，是「面向第三方 Agent 开放、查询时授权、跨应用、来源可追溯」四者同时满足的接口。以 donation 为主路径，capture 为受限兜底；被采集应用可以声明不入索引；查询结果的返回路径与接收进程同样受 ACL 约束。

## §6 接缝发现

**J4 记忆的写入授权与投毒（主责）**

- 攻击谱系已经完整（§3 Q7），这是一个已被证实的真实攻击面，不是假想威胁。
- 记忆条目从沙箱继承三样东西：写入主体身份与会话、会话的完整性等级（是否接触过不可信内容）、数据来源域。读取时按「读者当前权限 ∩ 条目标签」授权，低完整性条目读出后仍为低完整性。
- 给沙箱（C2）的输入：SBX-7「跨链不升级」要扩展到记忆路径——低完整性写入不能在后续会话里变成高完整性输入。
- 给记忆自身的输入：MEM-2 与 MEM-1 的分界要写清——Agent 决定「想记什么」，OS 决定「允不允许写、标什么来源」。

**J7 语义索引的常驻成本（主责）**

- 已知数据：嵌入模型约 200MB 级 [R34]；向量体积按维度和量化相差约 12 倍（估算）。
- 给内存管理（C4）的输入：嵌入模型纳入模型内存域，可驱逐、按事件加载；索引文件是文件页，记账应归属「记忆服务」而不是各应用。
- 给推理（C1）的输入：嵌入模型应由推理系统服务统一提供，避免每个应用各带一份。

**J1 有损驱逐 → 摘要入库（协同，主责内存管理）**

- 记忆侧结论：只在文本层做，必须可逆；系统提示词和技能前缀永远不摘要（会破坏前缀缓存命中）[E15]。
- 驱逐对象的分类规则（草案）：
  - 已决议的子任务输出 → 写文本摘要 + 原文指针；
  - 活跃推理上下文 → 交给内存管理降精度或换出；
  - 系统提示词、技能前缀 → 不摘要，保持前缀稳定。
- 质量与重算的成本对比，见 [C4 内存管理](C4-内存管理.md) 的驱逐去向成本模型。

**J8 端云路由与隐私标签（协同，主责推理）**

- 数据敏感度标签应来自记忆条目的数据域标签（确定性）；模型的情境判断只作补充（概率性）。
- 这意味着记忆框架要对推理的路由层暴露「标签查询」接口。

### 7.1 记忆系统对比表

**空白点清单**（按优先级）：

1. 面向第三方 Agent 的开放读取接口——所有对比对象都没有。
2. 查询时授权——Picker 先例不覆盖开放式查询，Gemini PI 只到应用级。
3. 写入完整性与隔离区——有攻击文献，没有商业产品的公开机制。
4. 来源标签与级联删除——商业产品只到条目级。
5. 被采集方排除权——Recall 事件中由应用自行阻止，OS 没有标准机制。
6. 结果返回路径受约束——TotalRecall Reloaded 的教训。
7. 资源成本基准——J7，几乎没有数据。
8. 国内厂商个人记忆的公开机制——荣耀、vivo、小米、OPPO 都没有找到资料。

**与最接近实现的差距**：

- **Apple**：机制层最接近（IndexedEntity），差在读取侧不对第三方开放、没有查询时授权；Siri 个人上下文的实际状态需要在定稿前核实。
- **三星 PDE**：TEE 与端侧留存最扎实，差在封闭。
- **Recall**：覆盖最广、安全工程最透明，差在授权粒度只到功能级、被采集方无话语权、结果路径未约束。
- **Magic Cue**：端云混合产品化最成熟，差在授权粒度不透明、第三方数据不可见。
- **HarmonyOS**：已有系统记忆和应用侧知识库能力，差在没有系统级跨应用索引，授权与 TEE 缺乏公开说明。

### 7.3 记忆形态选型表

「写入 / 读取成本」是定性判断。

| 形态 | 写入成本 | 读取成本 | 可解释性 | 可删除性 | 是否适合 OS 托管 | 依据 |
|---|---|---|---|---|---|---|
| 文本 / 文件 | 低（摘要需一次 LLM 调用） | 低到中 | 高（可读、可 diff、可用 git 管理） | 高（删文件即可，可审计） | **适合**：对象存储 + ACL + 版本 + 审计 | [E6][E8][E11][E24] |
| 向量索引 | 中（嵌入模型换代需全量重建） | 低 | 中低 | 中（要与原文同步删除） | **适合作为可选的系统服务**，不绑定索引结构 | MemoryAgentBench 中 BM25 41.5 高于嵌入式 RAG 29.8 [E2] |
| 知识图谱 | 高（实体抽取依赖 LLM） | 中 | 高 | 中（要清理关联边） | 不宜托管，由框架提供 | [E4][E8] |
| KV cache | 高（预填充或离线训练） | 命中时低；加载受闪存带宽限制 | 低 | 低（只能整块丢弃，绑定模型版本） | 适合作为内存管理托管的**缓存**，不作记录 | [E15][E17][E19] |
| 适配器 / 参数化 | 中到高 | 低（热插拔有延迟） | 极低 | 极低（无法精确遗忘） | 不适合作为记忆记录，归推理服务 | [E21] |
