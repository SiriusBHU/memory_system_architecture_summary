# R4 硬件亲和的模型架构寻优

> 日期：2026-11-09。本模块只补缺口：D2 §1 已有的 KV/token 表、M3 的 KV 与权重对比、2-场景与负载瓶颈 §2.2.5 的三档配置，不重复，直接引用并扩展。
> 联网预算：WebFetch 10 次、WebSearch 2 次（已用完 WebFetch）。KV 字节 = 2 × 全注意力层数 × KV 头数 × head_dim × 字节数；标「估算」的均由公开 config 自行推算。

## 1. 结论摘要

1. 硬件在环搜索的最完整公开样本是 LFM2：在 Galaxy S24 Ultra（Snapdragon 8 Gen 3）与 AMD Ryzen HX 370 的 CPU 上，用 ExecuTorch（8da4w）与 llama.cpp（Q4_0）实测，以 TTFT、decode 时延、4K/32K 峰值 RSS 为约束，搜索稳定收敛到「约 2/3 门控短卷积 + 1/3 GQA」的混合结构（论文，预印本）。
2. LFM2 的 NPU 没有进入搜索环：论文只把异构 NPU 列为设计目标，未给 NPU 测量；说明目前公开的「硬件在环」基本是 CPU 在环，NPU/PIM 在环是空白（预印本）。
3. 结构选择本身就是 KV 管理：LFM2-1.2B 仅 6 个注意力层、8 个 KV 头、head_dim 64，每 token KV 12 KiB（估算），是 Qwen3-4B（144 KiB）的 1/12；与 §2.2.5 的「三档相差 14 倍」同量级，且这一差距来自结构而不是系统优化。
4. 同一块 S25（Snapdragon 8 Elite，llama.cpp Q4_0）上，LFM2-1.2B 在 4K 上下文 prefill 222 tok/s、decode 55.5 tok/s，Qwen3-1.7B 为 98 / 26.9（厂商自报）；混合结构的优势随上下文增大而放大（Qwen3-4B 4K decode 11.4 tok/s）。
5. 内存/闪存亲和的结构设计已分为三类：KV 缩减（Gemma 3n 中层 KV 共享、Apple 层间共享 -37.5%、Qwen3-Next 3:1 线性/全注意力、Kimi Linear 称 KV 最多 -75%）、权重分层（Gemma 3n PLE、MatFormer）、IO 可预取（SmallThinker 注意力前路由，使专家在注意力计算期间从存储预取，Q4_0 下 4B 约 1 GB、21B 约 8 GB 内存）。
6. 学术上已有「线性化后再搜」的低成本路径：Jet-Nemotron 的 PostNAS 冻结预训练 MLP，只搜注意力块布局，2B 模型称 prefill 6.1 倍、生成吞吐最高 53.6 倍（NeurIPS 2025，GPU，具体硬件页面未写，待核实），但目标硬件是服务器 GPU，不是手机。
7. 2026-02 的 roofline 协同设计工作（arXiv 2602.10377）称：硬件协同使最优端侧架构趋向稀疏 MoE，同等时延下困惑度降 19.42%，INT8 使 Pareto 前沿向低时延移动（预印本，摘要口径）；对我们的含义是，选 MoE 底座需要由系统侧提供时延模型，而不是模型团队单方面决定。
8. 公开资料中没有 Apple、Google、Meta 的「模型团队 × 系统团队」协同流程的原始文档；只能从成品推断（Apple 称模型为 Apple silicon 优化设计；Gemma 3n 由 Google 与硬件厂商协同，待核实）。

## 3. 对关键技术的建议

### 对应的负载与瓶颈
- 基线 3B（4-bit，权重 1.7GB）decode 52 token/秒约需 52GB/s 带宽，占 LPDDR5X 理论峰值 77GB/s 的约 68%；T3 在 24K–32K 上下文时，基线 KV 为 820MiB–1.07GiB，重建 6–14 秒。
- 结构选择直接决定这两项：稠密 fp16 的重配置（Qwen3-4B）32K KV 为 4.5GiB，超出「Agent 侧可用约 4GB」；LFM2 或 Qwen3.5 类结构只有 0.38–1.0GiB，同一预算下可常驻多个会话。
- 但 OS 无法后加结构（M3 结论）。必须在模型选型/训练阶段把内存与带宽预算作为约束传给模型团队。

### 问题与挑战
1. 公开的硬件在环搜索几乎都是 CPU 在环（LFM2 为 S24 Ultra CPU 与 llama.cpp/ExecuTorch）；手机上真正承担 Agent 推理的是 NPU 与（未来）PIM，NPU 的算子支持与图编译约束（动态形状、卷积与线性注意力的支持度）无公开搜索成果。
2. 混合/线性结构对 NPU 友好度不明：LFM2 搜索只报告了 CPU；线性注意力的递推状态更新在 NPU 上是否高效，无公开测量，待核实。
3. 结构省下的 KV 常以质量风险换取：LFM2 质量来自内部 50+ 项评测（厂商自报）；Agent 的工具调用、长程精确引用对线性/滑窗结构的影响缺少独立评测，待核实。
4. 评估口径分裂：模型团队看困惑度与基准分，系统团队看 TTFT、RSS、闪存 IO；没有公开的统一代价模型。LFM2 把 RSS 与时延放进搜索是少见的例外。

### 量化目标建议值
| 指标 | 建议值 | 依据 |
|---|---|---|
| 候选底座的 fp16 KV/token | ≤ 35 KiB（基线 3B 的假设水平）；争取 ≤ 16 KiB | LFM2-1.2B 12 KiB、Qwen3.5-4B 32 KiB 已达到；Qwen3-4B 144 KiB 超标 |
| 32K 上下文 KV 常驻 | ≤ 1.1 GiB（int8） | 对应 T3 上限 1.07 GiB；Agent 侧可用约 4GB 的约 1/4 |
| 4K 上下文 decode | ≥ 50 tok/s，且 4K→32K 掉幅 ≤ 30% | 参考负载 52 tok/s；LFM2-1.2B 在 S25 CPU 上 1K→4K 掉幅 20%（69.8→55.5，厂商自报），Qwen3-1.7B 掉 32% |
| 每 token 活跃权重字节 | ≤ 1GB（稠密）；MoE 的热专家集 ≤ DRAM 驻留预算 | 参考负载 52GB/s ≈ 1GB×52 |
| 模型选型准入 | 必须提供 NPU 实测（非仅 CPU），含 4K 与 32K 的 TTFT 与峰值 RSS | LFM2 的搜索约束项可直接借用 |

### 模块级方案
1. 建立「选型准入卡」：每个候选底座按上表给出层数、KV 头、全注意力层数、滑窗与线性比例、每 token KV（fp16/int8）、固定状态、活跃权重字节，由系统侧自动从 config 生成。
2. 建立带宽与闪存代价模型：decode 时延 ≈ max（计算, 活跃权重字节/带宽 + KV 读取字节/带宽）+ 闪存缺失 IO；输入为 config 与目标 SoC 的实测带宽，给模型团队做搜索时的 Pareto 约束。LENS 一类把 NPU 当黑盒、用编译后端到端时延做预测的做法可借鉴（预印本）。
3. NPU 在环：把设备农场的 NPU 编译与实测接入搜索循环，补齐 LFM2 缺失的 NPU 数据；初期可用 PostNAS 式「冻结权重、只搜注意力布局」，降低搜索成本（Jet-Nemotron 思路，但需把目标由 GPU 改为手机 NPU）。
4. MoE 底座要求「可预取」：优先选注意力前路由（SmallThinker 路线）或每请求选专家（AFM 3 Core Advanced 路线，仅二手信息），使专家 IO 能与注意力计算重叠。
5. 与 R1/R5 联动：KV 缩减优先在结构层完成（本模块），推理侧稀疏选择与系统侧分页换出（R1、R5）作为补充，避免重复投入。

### 细节技术点
- 位宽与结构联动：INT8 可使 Pareto 前沿向低时延移动（roofline 工作，预印本）；Apple 为 2-bit QAT + 8 bit KV，必须在训练阶段完成（M3/D2）。
- 层间 KV 共享的位置：Gemma 3n 共享中层 KV 给上层，称 prefill 比 Gemma 3 4B 快 2 倍（官方，相对值）；Apple 共享使 KV 降 37.5%（官方，已有引用）。共享后 NPU 的 KV 缓冲可复用，属于 OS 记账要覆盖的场景。
- 滑窗层固定状态：滑窗 512 的层 KV 为固定值（Gemma 3n 约 16 MiB），不随任务增长，可视为常驻；全注意力层才进入分页与换出。
- PLE/MatFormer 的闪存放置：PLE 可放在 CPU/闪存侧、核心权重在加速器内存（官方），是「稀疏权重分层」的已量产先例；MatFormer 使同一份权重可在运行时按内存预算降档（E4B 内嵌 E2B）。

## 5. 与其他模块的边界
- 归本模块（推理服务的优化 → 硬件亲和的模型架构）：选型准入卡、代价模型、NPU 在环搜索、对模型团队提出的结构约束（KV/token、固定状态、可预取性）。
- 归 R1：推理侧稀疏注意力与 KV 选择（Quest、InfLLM v2、KVSwap），不改结构。
- 归 R2/R3：PIM、闪存内计算所需的结构形状（如 GEMV 友好、专家粒度）作为约束输入本模块，但硬件机制归 R2/R3。
- 归 R5/内存管理：专家命中率、预取、KV 分页换出、前缀缓存；本模块只提供「专家是否可预取」的结构条件。
